# 単体モードと「同期」の実装状況

## 現在使える機能

- **単体モード**：APK のネイティブライブラリ領域に Node / bash を配置し、対応する DSH・プラグインの ZIP をダウンロードして起動します。Termux アプリのインストールは不要です。Termux 起動の導線は代替手段であり、既定方式ではありません。
- **リモートモード**：PC とスマホが **同じ1つの Host** に接続します。Host がセッションストアを所有し、各クライアントがライブイベントを受信します。これが UI の「同期中」の意味です。
- **送信待ちキュー**：接続できない間の送信操作をセッション ID とともに保持します。詳しい再送・復旧手順は [remote-mode.md](remote-mode.md) を参照してください。

## 未実装の機能

**スマホ Host と PC Host の独立したストア間で、会話・プラグインを自動複製する機能は未実装です。** 同じ Wi-Fi に接続するだけで履歴がコピーされることはありません。

- `lib/discovery.js` は IPv4 UDP ブロードキャスト（ポート41234）の探索ヘルパーです。mDNS / Bonjour ではなく、現在の Host 起動処理に自動統合されていません。
- `lib/sync.js` と `lib/plugin-sync.js` は実験用のデータ操作ヘルパーです。単体テストの成功は実際の Host 間同期を保証しません。
- `GET/POST <pairPath>/sync` は **HTTP 501** と `{"status":"error","reason":"sync-not-implemented"}` を返します。イベントを保存せず成功を返す旧スタブは廃止しました。

## 将来実装する場合の要件（設計案であり、現在の保証ではありません）

1. ペアリング済みの相手だけを認証し、TLS で通信する。探索通知を信頼情報として扱わない。
2. Host ごとの永続的なデバイス ID と、上流 DSH のイベント形式・書き込み規約に適合するプロトコルを定義する。
3. 永続保存の成功後にだけ ACK を返す。再送の冪等性、同時書き込み、削除、時計ずれ、接続中断を検証する。
4. プラグインのバージョンだけでなく、構成・権限・機密情報の取り扱いを定義する。相手の広告だけで自動インストールしない。
5. 2つの実 Host を使った往復・障害・復旧テストを用意する。

ストアのファイルを稼働中に単純コピーして同期することは推奨しません。現時点で複数端末から同じ会話を使う方法は、共通 Host への接続です。
