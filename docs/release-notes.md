DeepSeek Harness を **スマホ単体で** 動かせるようにしたアプリです。
PC は要りません。スマホの中の Node が DSH の Host になり、同じ DSH の Web UI を
アプリ内の WebView で開きます。エージェントはスマホの画面を見て、タップ・
スワイプ・文字入力・アプリ起動ができます。PC の Host に接続する使い方も
残しています。

## v1.2.0 の変更点 — ログインできない・API キーが違う・UI が終わっている、を直しました

- **アカウントログインが通るようになりました**
  - 原因は WebView が `window.open` を返せないことでした。ログインの認可タブが
    開かないまま 10 分待って期限切れになっていました。`setSupportMultipleWindows`
    と `onCreateWindow` でアプリ内ポップアップとして開き、`/oauth/callback` まで
    WebView 内で完結させます。
  - すべての http(s) を外部ブラウザへ投げていたのを許可リスト方式に変更
    （Host 自身 / `127.0.0.1` / `*.deepseek.com` のみアプリ内）。
  - リモートモードではログインできない（Host 側のループバック callback に届かない）
    ことを UI と README に明記。
- **「API キーが違う」を切り分けられるように**
  - 入力欄の自動大文字化・自動補正を無効化し、前後の空白を落としてから送信。
  - メニューに「接続診断」を追加（モード / Host / 作業フォルダ / 資格情報ファイルの有無。
    秘密の値は表示しません）。
  - [`docs/troubleshooting.md`](troubleshooting.md) を追加（`AUTH` と
    `MISSING_CREDENTIAL` の違い、`/sdcard/DSH/.env` の罠、ログの見方）。
- **単体モードの UI をスマホ用に**
  - 根本原因: runtime にモバイル用クライアントプラグインが同梱されておらず、
    単体モードはデスクトップ UI がそのまま縮小表示されていました。`mobile-shell`
    パッケージとして runtime に同梱し、profile の行から読み込むようにしました。
  - 下部ナビ（新規 / 一覧 / 設定）、レールのタップ領域 44dp、本文 16px、
    composer の 680px 下限解除、welcome の余白圧縮、展開サイドバーの全画面化、
    Preview Notice の再表示抑止。
  - 起動直後にワークスペースを自動選択し、「Choose a workspace to start」で
    止まらないようにしました（単体モードのみ）。
- **安定性**
  - アプリ再起動時の `EADDRINUSE`（前回の Host の取り残し）を解消。ポートが
    取れない場合は別ポートで再試行します。
  - 401 を検知したら自動でペアリング画面へ復帰。Cookie の永続化、
    キーボード表示時のレイアウト、Android 15 の edge-to-edge 対応。
- **Host（PC 側）**
  - `pairPath` を変えてもペアリングページが壊れない。PIN のロック解除後に
    即再ロックされるバグを修正。
  - LAN アドレス選択で docker / WSL などの仮想アダプタを優先しない。

## v1.1.0 の変更点 — スマホ単体で動くようになりました

- **単体モード（既定）を追加**
  - スマホの中に **Node 26（Termux の aarch64 ビルド）と DSH のパッケージ
    ツリー**をインストールし、アプリがフォアグラウンドサービスとして Host を
    起動します。PC も LAN もペアリングも不要です。
  - 初回起動時にランタイム（約 130 MB）をダウンロードし、SHA-256 で検証して
    から展開します。以後はオフラインでも起動できます。
  - Android 10 以降は自分のデータ領域のバイナリを実行できないため、実行
    ファイルと共有ライブラリは APK の `jniLibs`（`lib*.so`）として同梱し、
    本来の名前（`bin/node` など）へのシンボリックリンクで起動します。
    APK 更新時はリンクだけ貼り直します（再ダウンロードなし）。
- **スマホ操作（Smartphone use）**
  - ユーザー補助サービス経由で、エージェントに次のツールを提供します:
    `phone_status` / `phone_screen` / `phone_nodes` / `phone_tap` /
    `phone_swipe` / `phone_type` / `phone_key` / `phone_apps` / `phone_launch`
  - Host（node）とアプリは **127.0.0.1 のループバック HTTP** で話します。
    トークンは起動ごとに生成し `$DSH_HOME/bridge.json` に置きます（外部公開なし）。
- **ファイルアクセス**
  - 「全ファイルアクセス」を許可すると、エージェントの作業場所が
    `/sdcard/DSH` になります。許可しない場合はアプリ専用領域で動きます。
- **DSH のブートを Android で成立させる**
  - DSH は起動時に Node の内部モジュールへ到達します。上流のネイティブ
    アドオンは Android 向けビルドが無いため、**JS の代替実装**を同梱し
    `--expose-internals` で起動します。
- **メニューの整理** — モード切替、権限、状態、Host の再起動、ランタイムの
  削除をアプリ内から行えます。

### 検証

- エミュレータ（API 35, x86_64）で、APK の初回インストール → ランタイム取得 →
  Host 起動 → DSH の画面表示 → ブリッジ経由の画面取得・タップ・スワイプ・
  日本語入力・アプリ起動まで確認しました。
- 実機（Android 16, arm64）でランタイム（同じ Node と DSH ツリー）が起動し、
  `dsh web` がループバックで待受・トークン交換できることを確認しました。

### 既知の制限

- スクリーンショットと `enter` キーは Android 11 以降（ユーザー補助の API）。
- 画面ロック中は Host を起動できません（Android がバックグラウンドからの
  フォアグラウンドサービス開始を拒否するため）。
- `node-pty` を使う端末タブは動きません（Android 向け prebuild が無い）。

## v1.0.6 の変更点

- **スマホ単独起動の足がかり（Termux 経由）**
  - メニューから「ローカルホストを起動 (Termux)」を選ぶと、Termux 経由で
    スマホ上で DSH ホストを起動し、`127.0.0.1:3080` に接続します。
    Termux が未インストールの場合はインストールページを開きます。
  - v1.1.0 では、この経路は **同梱ランタイムが起動できない端末のフォールバック**
    として残しています。
- **同一 Wi-Fi 同期の基盤**
  - `lib/sync.js` にセッション差分同期・プラグイン差分・同期判定の純粋関数を実装。
    ユニットテスト (`test/sync.test.js`) を追加。

## v1.0.5 の変更点

- **スマホでも独立したセッションを開けるようにしました**
  - これまでスマホ版は「PC でいま話している会話」に自動追従するだけだったので、
    スマホ側で新しい会話を始めることができませんでした。自動追従は初回起動時のみ
    行い、スマホ側で会話を切り替えたり新規作成したりしたあとは追従を止めます。
- **同じ Wi-Fi 接続時に全内容を自動同期するようにしました**
  - スマホがフォアグラウンドに戻ったときや、リンクが (再) 接続したときに、
    現在表示中の会話を自動で再取得します。PC 側で追加されたメッセージが、
    スマホ側で手動リロードなしに反映されます。入力中のメッセージは中断しません。

## v1.0.4 の変更点

- **ログイン時に自動でホストが起動するようにしました**
  - `dsh-mobile.ps1 install` で Windows の起動項目に登録し、ログインごとに
    ホストが立ち上がります。再起動したあとに「同期できない」になるのを防ぎます。
  - `dsh-mobile.ps1 uninstall` で解除できます。
  - ポートをすでに他のホストが使っている場合は何もしません（二重起動しません）。
- **ペアリングカードが壊れないようにしました**
  - カードの書き出しは一時ファイルへ書いてから置き換える方式に変更しました。
    ホストを書き込みの途中で終了しても、JSON が途中で切れたカードが残らない
    ようになりました（壊れたカードでは `status` が PIN を表示できません）。

## v1.0.3 の変更点

- **ホストを起動したターミナルを閉じても動き続けるようにしました**
  - これまで `dsh-mobile.ps1 start` の子プロセスとして起動していたため、
    起動元のシェルやセッションが終わるとホストも終了していました。
  - 起動を Explorer 経由の独立プロセスへ変更し、親プロセスに依存しない
    ようにしました。停止は `dsh-mobile.ps1 stop` です。
  - 併せて、ホストのログが `host.log` に出るようにしました。
- **セッションが失効したとき、原因と対処をアプリで明示するようにしました**
  - ホストがセッションを拒否した場合（HTTP 401/403）、それまで空白の
    ページが表示され、原因が分かりませんでした。
  - アプリは「ホストの認証が失効しました。PIN を入力して再ペアリングして
    ください。」と表示し、**「再ペアリング」ボタン**で PIN 入力画面へ移動します。

## v1.0.2 の変更点

- **起動時に PC の会話へ自動追従するようになりました**
  - プラグイン（`client.js`）が起動直後にセッション一覧を取得し、PC 側で
    最後に更新された会話へ自動で移動します。
- **サービスワーカーのキャッシュをバージョン化しました**

## v1.0.1 の変更点

**「履歴の読み込みに失敗しました」問題の修正（原因と対処）**

- 原因: スマホ/Web 側のホスト（`dsh web`）とデスクトップアプリの dsh の
  バージョンが異なっていたため、デスクトップアプリが書いたセッションログの
  イベント型（`job/registered` など）を解釈できず、履歴の読み込みを拒否して
  いました。
- 対処: CLI をデスクトップアプリと同じ版に更新します。

  ```powershell
  npm install -g @deepseek-ai/dsh@<デスクトップアプリと同じバージョン>
  ```

- dsh 0.2.1 以降、webserver はワイルドカード（`0.0.0.0`）への bind を
  拒否します。`dsh-mobile.ps1` は既定経路を持つ NIC の IPv4 を自動検出して
  具体的なアドレスに bind するようになりました。

## インストール

下の `app-release.apk` をダウンロードし、端末で「不明なソース」を許可して
開いてください（Android 7 以降）。初回起動時にランタイムをダウンロードします。

PC のホストに接続したい場合は、PC で `dsh-mobile.ps1 start` を実行し、
アプリのメニューから「PC のホストに接続する（リモート）」を選んでください。

- リポジトリ: https://github.com/tatudrag0n/dsh-mobile
- ランタイム: `dsh-mobile-runtime-arm64-v8a.zip` / `dsh-mobile-runtime-x86_64.zip`
  （アプリが ABI に応じて自動で選びます）
