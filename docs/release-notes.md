DeepSeek Harness を **スマホから**使うためのアプリです。

- PC の DSH ホストに **接続するだけのアプリ**（サーバー側は持ちません）
- 初回は接続先を入力し、PC に表示される 6 桁の PIN でペアリング
- 以降は cookie だけで自動接続。**トークンは URL に入りません**
- PC と同じホストのセッションを使うので、**会話がそのまま同期**されます

## v1.0.5 の変更点

- **スマホでも独立したセッションを開けるようにしました**
  - これまでスマホ版は「PC でいま話している会話」に自動追従するだけだったので、
    スマホ側で新しい会話を始めることができませんでした。自動追従は初回起動時のみ
    行い、スマホ側で会話を切り替えたり新規作成したりしたあとは追従を止めます。
- **同じ Wi-Fi 接続時に全内容を自動同期するようにしました**
  - スマホがフォアグラウンドに戻ったときや、リンクが (再) 接続したときに、
    現在表示中の会話を自動で再取得します。PC 側で追加されたメッセージが、
    スマホ側で手動リロードなしに反映されます。入力中のメッセージは中断しません。

## v1.0.4 の変更点

- **ログイン時に自動でホストが起動するようにしました**
  - `dsh-mobile.ps1 install` で Windows の起動項目に登録し、ログインごとに
    ホストが立ち上がります。再起動したあとに「同期できない」になるのを防ぎます。
  - `dsh-mobile.ps1 uninstall` で解除できます。
  - ポートをすでに他のホストが使っている場合は何もしません（二重起動しません）。
- **ペアリングカードが壊れないようにしました**
  - カードの書き出しは一時ファイルへ書いてから置き換える方式に変更しました。
    ホストを書き込みの途中で終了しても、JSON が途中で切れたカードが残らない
    ようになりました（壊れたカードでは `status` が PIN を表示できません）。

## v1.0.3 の変更点

- **ホストを起動したターミナルを閉じても動き続けるようにしました**
  - これまで `dsh-mobile.ps1 start` の子プロセスとして起動していたため、
    起動元のシェルやセッションが終わるとホストも終了していました。
    スマホが「同期できない」になる原因でした。
  - 起動を Explorer 経由の独立プロセスへ変更し、親プロセスに依存しない
    ようにしました。停止は `dsh-mobile.ps1 stop` です。
  - 併せて、ホストのログが `host.log` に出るようにしました（以前は出力が
    空で、障害の原因をログから追えませんでした）。
- **セッションが失効したとき、原因と対処をアプリで明示するようにしました**
  - ホストがセッションを拒否した場合（HTTP 401/403）、それまで空白の
    ページが表示され、「同期できない」の原因が分かりませんでした。
  - アプリは「ホストの認証が失効しました。PIN を入力して再ペアリングして
    ください。」と表示し、**「再ペアリング」ボタン**で PIN 入力画面へ
    移動します。
- ホストを再起動しても**スマホ側は再ペアリング不要**です（セッション cookie は
  30 日有効で、ホスト再起動でも失効しません）。
- APK の versionName を 1.0.3 に更新しました。

## v1.0.2 の変更点

- **起動時に PC の会話へ自動追従するようになりました**
  - これまでスマホのアプリは、ホストが復元する空セッション（履歴なし）を
    そのまま開いていました。履歴が読めない empty な画面に見える状態でした。
  - プラグイン（`client.js`）が起動直後にセッション一覧を取得し、**PC 側で
    最後に更新された会話（blank でない最新のセッション）へ自動で移動**します。
  - ユーザーがスマホ側で入力を始めたセッション（blank でないもの）は変更しません。
- **サービスワーカーのキャッシュをバージョン化しました**
  - `/sw.js` のキャッシュ名がクライアント資産のハッシュを含むようになり、
    プラグインを更新してもブラウザが古い JS を返し続け的情形を避けました。
- APK の versionName を 1.0.2 に更新しました（機能自体はホスト側のプラグインの
  変更で、APK の内容は WebView ラッパーのみの小さい更新です）。

## v1.0.1 の変更点

**「履歴の読み込みに失敗しました」問題の修正（原因と対処）**

- 原因: スマホ/Web 側のホスト（`dsh web`）とデスクトップアプリの **dsh の
  バージョンが異なっていた**ため、デスクトップアプリが書いたセッションログの
  イベント型（`job/registered` など）を解釈できず、履歴の読み込みを拒否して
  いました。
- 対処: CLI をデスクトップアプリと同じ版に更新します。

  ```powershell
  npm install -g @deepseek-ai/dsh@<デスクトップアプリと同じバージョン>
  ```

  `dsh-mobile.ps1 start` は起動時に CLI とデスクトップアプリの版を突き合わせ、
  違う場合は警告と修正コマンドを表示します。

- dsh 0.2.1 以降、webserver はワイルドカード（`0.0.0.0`）への bind を
  拒否します。`dsh-mobile.ps1` は既定経路を持つ NIC の IPv4 を自動検出して
  具体的なアドレスに bind するようになりました。
- `dsh-mobile.ps1 status` / `stop` が NIC アドレスを自動検出した
  ホストを正しく判定するように修正しました。

## インストール

下の `app-release.apk` をダウンロードし、端末で「不明なソース」を許可して
開いてください（Android 7 以降）。同じキーで署名したアプリなので、公開
リポジトリからの配布でもそのまま更新できます。

接続先のアドレスは、PC で `dsh-mobile.ps1 start` を実行したときのカードに
表示されます（例 `192.168.0.166:3080`）。

- リポジトリ: https://github.com/tatudrag0n/dsh-mobile
- 中身: WebView アプリ（依存ゼロ、APK 約 29 KB）
